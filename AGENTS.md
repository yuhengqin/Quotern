上半部手维护。`<!-- HEROUI-REACT-AGENTS-MD-START -->` 以下由 `heroui agents-md --react --output AGENTS.md` 整段覆盖。

本仓库无后端。脚本以根 `package.json` 为准。

| 路径 | 职责 |
|------|------|
| `packages/core` | parser、queue、sync、local-api |
| `packages/cli` | `quotern`：HTTP + 托管 dashboard dist |
| `packages/dashboard` | CLI 内置面板与可独立部署的浏览器面板 |
| `apps/desktop` | Electron；`src/renderer` 与 dashboard **同构但独立** |

改 `packages/dashboard/src` 的共享 UI / 数据层时，核对该路径在 `apps/desktop/src/renderer` 是否有同名副本，有则一起改完。

PR / 分支命名 / 本地开发：[CONTRIBUTING.md](CONTRIBUTING.md)。Desktop 主进程、IPC、heartbeat：[apps/desktop/README.md](apps/desktop/README.md)。

维护注意事项：[架构](docs/architecture-notes.md)、[数据采集与统计](docs/data-notes.md)、[运行维护](docs/runtime-notes.md)、[开发协作](docs/development-notes.md)。

## UI 开发

- 新增或修改 Dashboard / Desktop UI 前，必须阅读并遵守 [UI 组件与交互规范](docs/ui-guidelines.md) 的总则及相关组件章节。
- 优先复用已登记的公共组件；能力不足先评估扩展。筛选菜单使用 `components/FilterMenu`，独立实现或例外须在变更说明中记录原因与验收结果。
- 新增、调整或弃用公共 UI 入口时，同步更新规范中的路径、适用边界、使用点和跨端共享方式。

## 功能保留与验收

功能改进、升级或重构，默认保留原有展示信息、交互和功能。完成前必须对照改动前的行为，确认没有意外缺失；验收同时检查新能力是否实现、旧能力是否保留。

如需删减或改变原有能力，且超出用户已明确要求的范围，先说明影响并获得用户确认。

## 工作区与服务归属

开始开发、操作 worktree / 分支或管理开发服务前，必须阅读并遵守 [worktree 开发规范](docs/worktree-development.md)。已有 worktree 不等于正在并行开发。没有并行开发且 main 工作区完全干净时，直接在 main 开发；否则使用独立分支和 worktree。

服务归属和隔离规则始终生效，包括直接在 main 开发时：使用隔离的 `pnpm dev:*` 入口；端口冲突不得停止其他会话的服务。只清理本会话可核实归属的进程、文件和分支，归属不明时保留并报告。

## 开发指南

发布产物需要 Node.js >= 20.10；仓库开发和测试使用 Node.js 22.13+。安装依赖与执行仓库脚本统一使用 `corepack pnpm`，版本以根 `package.json` 的 `packageManager` 为准。

克隆或新建 worktree 后，需要安装依赖时在仓库根执行 `corepack pnpm install --frozen-lockfile --prefer-offline`。依赖共享由 `pnpm-workspace.yaml` 的全局虚拟存储配置管理，禁止手动复制或链接其他 worktree 的 `node_modules`；依赖变更、已有安装迁移和共享存储清理必须遵守 [依赖初始化与共享](docs/worktree-development.md#依赖初始化与共享)。

如 `pnpm install` 卡在 electron postinstall

Electron 二进制默认从 GitHub Releases 拉取；国内网络可能会超时

请在安装前设置环境变量：

```bash
# Git Bash / macOS / Linux
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
export ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
corepack pnpm install --frozen-lockfile --prefer-offline
```

```powershell
# PowerShell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
corepack pnpm install --frozen-lockfile --prefer-offline
```

## 契约

`packages/core/src/server/local-api.ts` 的 `/functions/tud-*` 是本地面板契约。Dashboard 经 HTTP 读取 CLI；Desktop renderer 经 IPC 走同一套内存 local-api，不占 `:8452`。路由、响应与参数见架构注意事项。

定价：`packages/core/src/pricing/pricing.json` 是内置底表。启动时先读有效磁盘覆盖缓存；仅显式配置远端地址时请求一次覆盖表，失败保留已有价格。旧失效默认地址会迁移为空，自定义地址保留。

## Runtime

数据目录 `~/.quotern/`（`packages/core/src/paths.ts`），日志 `~/.quotern/logs/`。

`tud.pid`（`{pid,kind}`，`kind` ∈ `{cli,desktop}`）互斥：Desktop 启动停 CLI 并抢 owner；之后 CLI `start` 只开面板（observer），不创建常驻采集调度。

## Dashboard 进 CLI 包

`pnpm start:cli` 先执行 `pnpm build:cli` 再托管 dist，使用正式运行数据。直接运行已构建的 CLI 包时，修改 Dashboard 后需要重新构建。并行开发使用 `pnpm dev:cli`，提供 Vite HMR 与独立 CLI；实际端口、数据目录和会话归属见启动输出及 `pnpm dev:status`。

CLI 构建固定 `VITE_BASE=/`。子路径在构建环境注入 `PUBLIC_PATH` / `VITE_BASE`；写进已提交的 `.env.development` / `.env.production` 会打进 CLI 包。

## Desktop 发版

`pnpm release:desktop:mac|win` 推 GitHub Release。`electron-builder.yml` 的 `publish` 指向 `yuhengqin/Quotern`；运行时更新读取构建生成的 `app-update.yml`。私有仓库更新需客户端环境提供 `GH_TOKEN` / `GITHUB_TOKEN`。Electron 二进制走 `apps/desktop/.npmrc` 国内镜像；根 `pnpm.onlyBuiltDependencies` 已含 `electron`。
