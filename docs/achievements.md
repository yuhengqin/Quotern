# 成就与个人足迹

Desktop 与 CLI 浏览器面板均可从用量页顶部的奖章入口、热力图下方的活跃记录入口进入成就页。成就页包含三枚徽章展示架、最近获得、正在接近、个人纪录、年度足迹和全部收藏。收藏区按 14 个系列各展示一张主卡；打开系列详情可搜索各 Agent、项目及周期记录，并查看或展示早期获得的等级。

系列卡使用“已与 2 个 Agent 达成”“已收藏 4 个月”等记录数，不把对象数量当作完成分母。“正在接近”每系列最多一个目标，过期未达成月份保留在详情的历史记录中。

## 全部系列

| 系列 | 达成条件 |
| --- | --- |
| 初次记录 | 首个 Token 大于 0 的活跃日 |
| Token 里程碑 | 累计 100 万、1000 万、1 亿、10 亿 Token |
| 会话里程碑 | 累计 10、100、1000 个去重会话 |
| 累计活跃 | 累计 7、30、100、365 个活跃日 |
| 连续记录 | 最长连续 3、7、30、100 日 |
| 月度全勤 | 自然月每一天都有记录；月底结束后点亮“月度肝帝”全勤章 |
| 月度活跃 | 自然月中累计活跃 20 日，每月独立收藏 |
| 算力足迹 | 累计预估费用达到 $10、$100、$1000 |
| 会话时光 | 会话首末消息跨度累计达到 10、100、1000 小时 |
| 一路同行 | 同一 Agent 累计活跃 30、100 日 |
| 多面手 | 2、3、5 种 Agent，且各自至少活跃 3 日 |
| 项目长跑 | 同一仓库或已确认的项目根目录累计有逻辑会话消息 30、100 日 |
| 个人纪录 | 历史最长连续、单月最多活跃日；保留个人最佳 |
| 年度足迹 | 每个有记录的自然年结束后获得年度章；当年可提前分享进行中的年度卡 |

## 自动点亮与提示

满足条件后自动保存，无需手动领取。新获得的徽章合并为一条轻提示，点击后查看详情；不会自动弹出阻断操作的弹窗。首次导入历史记录也只合并提示一次。入口圆点表示尚未打开查看的成就；关闭提示与已读状态分别保存，错过提示不会丢失成就。

可在成就页关闭“成就提示”。关闭期间仍记录达成结果，之后开启不会补弹关闭期间的旧提示。已获得徽章永久保留，后续日志删除、历史纠正或价格变化不会撤销。历史回补可以提前达成日期，不会再次庆祝同一枚徽章。

## 数据口径

- 按 `Asia/Shanghai` 自然日计算，活跃日要求当日已采集 Token 大于 0。当前连续天数在今天尚未使用时可延续至昨天。未来记录和无效日期不参与计算。
- 读取本地已采集的完整队列与会话元数据，不受用量页日期、Agent、项目筛选影响。“完整”指已采集历史，不能恢复从未采集且已删除的日志。
- Token 按输入、输出、缓存读、缓存写、推理五项计算；同桶以最后版本为准，不把重复快照相加。
- 会话按来源与逻辑会话 ID 去重；时长为各会话首末消息跨度相加，包含闲置与并发，不能解释为人的专注时长。未覆盖的会话来源会在页面标明。
- 算力足迹使用现有价格表计算的预估费用，不能解释为实际支付。达成时的快照保留，当前进度可随计价表变化。
- 项目长跑目前覆盖 Claude/Codex 的明确绝对 `cwd`，按逻辑消息日期计算，同一天跨 Agent 只计一次。最近的 Git 仓库优先于目录中的项目配置；关联 worktree 使用共同 Git 目录归属，子目录合并到同一仓库，独立 clone 不按远端 URL 或名称合并。
- 非 Git 目录识别最近的 `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、`pom.xml`、Gradle、CMake、Composer 或 `.project` 配置根。缺少证据、目录已删除或来自其他操作系统的目录列为“待确认”，不自动授予新的项目成就；在“项目长跑 → 管理项目”中确认、重命名、合并、撤回合并或忽略。合并按日期集合去重；忽略和撤回确认不会撤销已有徽章。
- 项目身份使用完整根路径的哈希，显示末级名称；同名不同身份附短标识，可重命名区分。不保存完整 cwd；Windows 普通与扩展路径统一，百分号保持原义。旧 cwd 哈希与已验证项目根之间的别名映射会保留，供旧缓存、展示架与收藏迁移使用。
- 自然月按实际 28–31 日判断。月度全勤及年度章在周期结束后结算，后续打开页面、聚焦或同步时会重新检查；允许晚同步补发。

## 展示与分享

最多展示三枚已获得徽章。“使用推荐组合”优先选择不同系列，也可自行选择同系列的不同 Agent、项目或等级。分享支持单枚徽章、展示架、年度卡，先预览再复制或下载 PNG。最近获得、接近目标、展示架、单枚详情和分享统一显示“成就名 · Agent / 项目”，周期章保留年月名称。

费用与项目名称默认隐藏，只有显式打开相应开关才进入导出内容。年度卡的统计限定为所选年份，附带徽章标注该年的点亮日期，避免将累计数值误读为当年用量。图片由本地页面生成，功能不会自动发布到外部平台。

## 存储与客户端

状态保存在 `~/.quotern/achievements/state.json`，独立于用量缓存。跨进程锁内重读合并并原子替换，Desktop 与 CLI 通过同一数据目录共享已获得、已读、提示和展示架设置；损坏文件保留并明确报错。

Core 的 `/functions/tud-achievements` 提供 GET 快照与 POST `claim-notice`、`seen`、`preferences`、`project` 操作。快照附带项目候选与项目设置，`project` 接受项目 id、名称、确认、忽略及合并目标，拒绝未知项目和合并循环。HTTP 和 Desktop IPC 共用同一路由，Desktop 无需额外启动 HTTP 服务。通知在锁内一次性领取；客户端也按顺序提交状态操作，避免刷新覆盖刚保存的设置。

会话缓存 Schema 6 接受并升级旧 Schema 3–5：日志仍存在时重新读取根目录证据，已删除日志的已有消息元数据继续保留。原始已获得记录不因合并而删除，当前显示按项目归属投影；合并视图按日期并集计算达成时间，并保留已有较大快照。原始对象的日期只按其自身证据修正，撤回手动合并可恢复各自日期与快照，已读状态与展示架随映射解析，不为同一旧徽章重新通知。后续自动根目录识别吸收既有手动合并时，会规范化设置并消除身份归并产生的冗余自环。

路径哈希是身份标识，并非对低熵目录名称的加密保护；公开分享默认不包含项目名称或身份字段。
