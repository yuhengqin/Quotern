# 版本发布说明

这里保存 GitHub Release 的用户说明，每个 Desktop 版本一个 Markdown 文件，例如 `v0.1.13.md`；预发布使用完整版本号，例如 `v0.1.14-beta.1.md`。文件名必须与 tag 完全一致。

- 各包 `CHANGELOG.md` 由 Changesets 按版本累计，保留完整变更记录。
- 本目录的版本文件整理本次发布的用户重点、升级注意事项和下载提示，可以汇总 Desktop、CLI 和 Web 的相关变化。
- 在生成版本号和 CHANGELOG 后整理说明，核对真实变更，一起提交，再打 tag。模板与具体步骤见 [发布规范](../../RELEASE.md#release-正文模板)。

显式手动创建草稿时，workflow 会先检查对应版本文件存在且非空，再通过 `--notes-file` 导入正文。普通构建验证不强制要求该文件；最终公开发布仍由人工完成。修改仓库文件不会自动同步到已经创建的 Release；需要显式更新草稿正文。

`v0.1.13.md` 根据现有 0.1.13 CHANGELOG 补充，作为版本说明的起点，不包含后续尚未升版的改动，也不会更新线上已有的 Release。
