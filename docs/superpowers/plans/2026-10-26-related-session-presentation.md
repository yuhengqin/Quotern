# 关联会话展开区优化

> **For agentic workers:** 使用 superpowers:executing-plans 逐项执行；用户已授权以下五点，直接完成实现和验收。

**Goal:** 让展开后的关联会话更易辨认，同时保持主表列对齐及已有功能。

**Design / Spec:** 沿用现有字体、颜色 token 及 HeroUI 筛选菜单。父行展开后使用浅 accent 底和标记，与中性悬停反馈区分；关联区使用轻竖线。局部工具栏将“关联会话”与紧凑模型筛选相邻排列，单模型显示静态模型名。名称优先真实标题，其次可信代理昵称、角色，最后未命名提示；角色有明确标签，无真实标题时短 ID 在独立辅助行显示。展开控件、来源图标与名称同步缩进，宽屏项目、时间和数字保持与主表对齐。窄屏优先完整名称和短 ID，角色可从读屏、完整提示及详情访问；深层节点数字另起一行，元信息与数字避开树线。宽屏继承主表列头时子行隐藏重复 Token 后缀，窄屏与无列头预览保留。

**Architecture:** 在 Core 已缓存的 metadata 分组处通过 relation 透传两个可选身份字段，不调用详情 enrichment、不读取正文推导名称。Dashboard/ Desktop 共用 SessionActivityPanel，复用既有 FilterMenu、数字格式化和旧 runtime 的 insights 回退。名称搜索同步识别这两个可信字段，保持现有模型分支筛选语义和状态、分页、详情、导出及原始数值。

**Tech Stack:** TypeScript、React、HeroUI v3、Tailwind 容器查询、Core HTTP/IPC。

## Constraints and review focus

- 新可选字段必须兼容缺字段的旧 runtime；真实标题始终优先，元数据缺失不虚构名字。
- 局部模型筛选不修改父行及用量；多层关联仍可展开，选择折叠后保留。
- 嵌套区域不能缩窄宽屏整行容器，项目/时间/Token/费用横坐标需实际 DOM 验证；窄屏另行检查节点、元信息与数字无叠压。
- 375px 窄屏、长昵称/角色、多个模型和单模型静态状态均可达，无横向溢出。
- 不新增汇总、精确值入口，不改变费用精度、未知/零值和单位设置。
