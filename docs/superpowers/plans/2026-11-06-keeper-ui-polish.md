# Keeper 对照后的六项界面优化

用户已要求落实六项对照建议。保持现有统计口径、所有详情信息、四语言与 Dashboard / Desktop 共用路径。

1. 性能：图例、名称、单位、当天样本数；比较表可排序，最多 4 个模型同图（原始全量样本聚合），模型入口筛选样本。未知值排末尾。
2. 返回：会话链接携带经校验的性能筛选上下文；明确“性能样本关联会话”，返回恢复筛选和滚动。通知入口保持原行为。
3. 额度：同一对话框内“当前额度 / 历史”，历史按需读取；展示本地化窗口、周期边界及状态，观测时间和真实周期边界分开，不推测未知起点。
4. 价格：列表行预填精确模型 ID，共用编辑器可搜索及手填 ID；参考价、当前及修改后生效价预览，字段错误就地关联，保留草稿。
5. 更新：保留旧 API 的同步契约，新客户端可查询实际保存和重算状态；显示本机历史估算范围，来源上报费用保留，失败明确且可重试。不能将失败伪装成后台待更新。
6. 验收：有意义的算法 / 导航 / API 测试；构建两端；现有 keeper smoke 扩展到单弹窗、排序比较返回、价格预览和状态；截图与键盘、390px 检查。

执行顺序：性能与导航 → 额度 → 价格契约和编辑器 → 两端验证和独立审查。主代理实现；只读调查已完成。主工作区干净且无并行开发，依仓库规则直接 main；隔离服务仅管理本会话拥有的实例。未授权发布。

审查重点：样本截断不影响聚合、未知值排序、任意模型 ID 不进入 CSS key、返回参数不允许任意跳转、账号变化不显示过期历史、价格并发版本冲突、重算失败后读取完整性、旧运行端兼容、双端样式扫描路径。

完成验收：`corepack pnpm test` 通过（包含按平台跳过的用例），两端类型检查通过；独立审查发现的三项问题已修复，并补验旧运行端比较回退、按任务 ID 查询及稀疏模型数据点。Electron 使用独立合成数据和真实 Core / IPC 完成排序、比较、会话返回、价格校验、保存与失败重试、状态丢失恢复、单弹窗历史、390px、单位设置和四语言切换。Chrome 经独立 CLI 的 HTTP 完成比较、行预填、价格预览、测试价格保存 / 重算 / 恢复及 390px 表单检查。测试价格已恢复，预览保留在本会话的隔离服务；未打包安装器或发布。
