# 本机共享背景图库

用户已确认将分享背景图库交给 Core，浏览器与 Desktop 共用，并迁移已有素材。

## 归属与兼容

- 图库属于 Core 的 `dataDir`，默认 `~/.quotern/share-backgrounds/`。相同数据目录的 CLI、Desktop 和不同浏览器共用；不同数据目录相互独立。
- 保留最多三张、2 MB/张、固定 2:3 裁剪、最新保存图默认选中以及明确替换的现行行为。当前选择属于分享会话，不共享。
- 继续保存裁剪成品；此次不改裁剪工作流，也无法恢复旧图库没有保存的原图。

## 存储与接口

- Core 管理图片二进制与版本化 `index.json`；图片按内容哈希命名，索引仅含元数据和迁移收据。
- 每次操作在独立跨进程文件锁内读取最新状态。图片先准备、索引原子替换成功后才清理无引用图片。CLI observer 也可能写入，不能依赖采集 owner 锁。
- `GET /functions/tud-share-backgrounds` 读取；`POST` 处理 add、remove、touch、import。响应仍为 local-api JSON envelope，图片作为 Data URL 通过 HTTP/通用 Desktop IPC 返回，避免额外文件系统访问入口。
- Core 验证格式、真实文件类型、尺寸、大小、ID、名称和时间；请求体有上限。无效存储保留原文件并返回可恢复错误。

## 迁移

- 打开分享时读取旧浏览器 IndexedDB；Desktop 的专用 IPC 只读取旧 userData JSON，正常操作全部走 Core API。
- 自动导入空位中的旧图，按内容去重，保留创建和使用时间。满额时不覆盖，返回待导入项，界面说明可删除共享图后重试。
- Core 持久化以图片内容计算的迁移收据。同一张旧图在其他浏览器拥有不同 ID，也不会因重试、响应丢失、不同进程并发或删除后再次打开而重复导入或复活。
- 不删除旧 IndexedDB 或 JSON，保留备份。图库可用但迁移失败时显示独立提示，可重试；图库读取失败则禁止保存。
- 浏览器仅能读取当前浏览器/当前 origin 的旧库，需要在原来使用过的浏览器和地址打开一次。Desktop 首次打开分享触发旧 JSON 迁移。

## 刷新与验收

- 每次打开分享读取共享库；窗口重新获得焦点时刷新，保留仍存在的当前选择。提供刷新/重试入口，打开的其他端无需重新启动。
- 自动测试覆盖两个 API 实例共用文件、独立子进程并发、三张上限、显式替换、无效输入不改变文件、导入去重/满额/重试/删除后不复活、Desktop 旧文件读取和浏览器迁移协调。
- 执行 `pnpm test` 和 Desktop `typecheck`；以独立数据目录运行 HTTP 探针，避免修改用户真实图库。
