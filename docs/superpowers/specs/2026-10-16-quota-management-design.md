# 额度管理设计

用户已确认按 AgentGauge 对照分析的建议顺序完整实现，并要求独立分支、worktree 和验证。

## 范围与成功条件

- 动态窗口保留供应商稳定 ID、模型分组、实际周期及重置时间；Codex 额外限制和重置次数、Claude 模型专项限制可展示，超过三条可展开。
- Desktop 主进程统一后台读取已有 12 个订阅通道；窗口关闭仍可提醒。采样、刷新和失败状态与 renderer 生命周期分离。
- 阈值跨越通知和额度重置通知分别可开关。首次观察、切换账号、重新启用及旧缓存不重放提醒；每个窗口每个周期阈值只提醒一次。
- 额度历史保存 90 天，只保存最新有效读数和不可逆账号键，不保存凭据；采样失败与缓存重播不生成样本。读写失败不影响既有额度显示。
- 节奏支持均匀、工作日和自动模式。缺少周期/重置证据不计算；自动模式至少 14 个不同本地日期，否则退回均匀。
- 最近六小时微型额度趋势；近 90 分钟至少三次样本且跨度 30 分钟，斜率为正、预计耗尽早于重置时才显示估算。周期切换后不拟合上个周期；过期读数不显示当前预测。
- 服务商公开状态与账号/额度失败独立；失败标未知或保留原时间，不伪装正常，链接仅允许预配置官方状态页。
- 刷新区分周期、交互与恢复；按 provider 基础间隔、自适应空闲/锁屏、429 Retry-After/退避、冷启动和并发合并处理。冷却与陈旧状态可见。
- Windows 使用既有 Electron 托盘面板，保留主窗口入口；托盘摘要/图标表达最紧张额度并显示文字。macOS 行为保持兼容。

## 架构

在 Desktop shared 新增可测试的额度模型与纯计算模块，在 main 新增额度管理服务、持久化和公共状态读取。既有 reader 保留原始专有字段，增加可选规范窗口与不可逆身份键。公开 IPC 只传展示状态和偏好；凭据、底层错误、完整供应商响应不进入 IPC。

主进程订阅管理器统一消费各 reader，主窗口/托盘额度区域改用同一管理快照。设置使用主进程偏好持久化，开启/关闭通道同时控制轮询和通知。宠物复用规范窗口，不将 0%/100% 过滤规则用于告警。浏览器 Dashboard 的既有本地 Token 统计契约保持；本次额度能力接在现有 Desktop 订阅域。

历史按 provider + account identity + window ID 隔离；身份不明时不持久化/预测，界面明确缺少可用历史。周期身份以供应商 reset timestamp 为主，吸收一分钟抖动。不能将利用率小幅回调当重置。身份变更或认证丢失清当前分析基线。

不增加产品依赖。使用现有 React/HeroUI/Electron/Node 和原子文件写入；本地开发使用 pnpm dev:desktop 的独立数据目录，测试全部使用虚构凭据/快照和临时目录。

## 验证

纯算法覆盖窗口归一化、时间边界、通知去重、工作日/自动节奏、周期切换与 ETA 门槛。服务测试覆盖真实新读数、账号切换、并发、限流、保存损坏/失败、关闭通道、退出和恢复。运行 Desktop 测试、typecheck、全仓 pnpm test；隔离 Electron 启动验证托盘与设置，受控界面数据验证展开/微型图/窄屏/键盘操作。分别报告自动化、受控界面和真实账号结果，不把未提供的额度当成零。
