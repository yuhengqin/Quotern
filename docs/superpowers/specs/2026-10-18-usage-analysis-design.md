# 第二、三批用量分析能力

用户已授权实现前次评估的第二、三批，并要求多 Agent 协作。第一批的计量完整性、费用解释与 CLI 报告沿用当前 main；本次交付五项能力：会话费用下钻、模型费用趋势、精细计价、图表独立时间粒度、Claude statusline。

## 数据与行为

- 扩展已有 SessionObservation，不给半小时桶猜 sessionId。观测保存可选五类 Token 拆分、请求级计价证据；schema 升级回扫仍存在的日志，已删除日志的旧读数保持可读并明确缺失。会话聚合沿用同一去重/fork/日期过滤路径，返回模型明细、已知费用、完整性和相同范围的任务计时。会话累计来源金额不按模型比例分摊。
- 新增 Core 时间×模型趋势投影。小时保留日期，周一为周界，周/月裁剪选定范围；按来源/日期直接过滤桶，再计算费用，禁止按 Token 比例分摊。补齐范围内空桶，今天不生成未来小时。未计价保留已知小计及缺失信息。
- 两端现有趋势区保留 Token 全部/详细与 Token/费用模式，增加小时/日/周/月选择和按模型视图；范围筛选、分享及概览不随图表粒度变化。模型颜色稳定，较多模型可汇入明确的其他项。会话弹窗补项目过滤、排序和模型明细；保持首页六条。
- 精细计价使用请求原始证据：服务档位、缓存 5m/1h、完整请求输入、请求时间。支持显式规则的 TTL、整请求长上下文和有生效日期的价格；规则缺失不能猜倍率。原始 Token 与主用量桶不重复计入。旧数据无证据时继续按原有估价并标记限制。
- `quotern statusline` 从 stdin 读取 Claude 数值元数据，优先使用宿主的会话金额及上下文，今日本地费用复用只读报告。输出一行，清除控制字符，未知不归零；不启动 runtime、不联网、不注册或改写用户 hook。

## 协作与验证

main 初始完全干净，无其他开发会话活动，按仓库规则直接在 main 执行。主代理负责设计及业务语义实现；code_explorer 只读调查，mechanical_editor 只处理明确的镜像/文案机械修改，verifier 运行限定检查，reviewer 独立审查。所有开发服务使用隔离入口。

测试覆盖跨日期/来源、请求阈值与累计值区分、流式快照、未知费用、schema 历史兼容、小时/周/月边界、statusline 零值/坏输入/终端转义。最终运行构建、两端类型检查、相关及全量测试，并检查真实浏览器渲染。
