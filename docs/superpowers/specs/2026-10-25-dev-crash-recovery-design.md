# Windows 开发会话异常恢复

目标：关闭终端、强杀开发主管或其外层进程树后，下次 `dev:*` 能自动恢复所属资源，同时保留活跃会话、其他 worktree 和无关进程。

现有问题：detached Node guardian 仍属于原进程的后代，外层 Job 或 `taskkill /T` 可将它一起清理；唯一退出凭据随之丢失。监视者只等待孤儿自行退出，也可能一直无法完成。

## 方案与取舍

- 仅按端口、直接子 PID 或 Job 名称消失清锁：无法证明完整后代结束，排除。
- 增加同树监视者：仍可能一起退出，不能解决外层进程树强杀。
- 采用本机 WMI 创建隐藏、breakaway 的 guardian，通过随机会话命名管道握手；持有原 supervisor 句柄和原 Job，主管退出后清理这个 Job，查询归零后发布凭据。采用此方案，不增加 npm 依赖。

## 约束

- 所有构建和服务必须等 guardian 握手及 Job 归属成功后才启动。
- 恢复不向历史 PID 发信号；guardian 仅通过已持有的 Job 清理已确认所属后代。
- 完成凭据校验完整会话身份及 proofToken；有效凭据优先于裸 PID 探测，避免 PID 重用误阻塞。
- Job 名称不存在、访问失败、全部观察者消失都不等于整个进程树结束。无法证实时继续保留锁。
- 兼容已有 v1 正常退出凭据。POSIX 进程组策略不变。
- 资源获取、恢复和释放仍串行；不得以超时直接接管 guard。
- Job 确认归零后，guardian 在原进程句柄仍固定时清理该 supervisor 的普通 guard；外来 PID、链接和未知内容保留。监视者建立之前的遗留 guard、全部观察者消失或系统断电而无证明仍保守保留。

## 验收

受控临时目录中覆盖：外层进程树强杀、主管强杀后的所属孤儿收尾、监视者丢失时仍拒绝无证据恢复、有效凭据伴随历史 PID 复用、并发恢复单一赢家，以及另一独立 CLI/Vite 实例持续响应。不得扫描真实用户来源或结束其他服务。
