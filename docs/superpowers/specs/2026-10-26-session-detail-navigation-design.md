# 会话详情内导航

用户已确认：默认在同一弹窗查看关联会话，支持返回；保留浏览器新标签页、Desktop 独立窗口的辅助入口。

- 同一 Modal 内维护查看栈。进入子会话后显示返回按钮，父会话的用量范围、折叠项、滚动位置和触发器焦点可恢复；多层逐层返回，关闭退出整个详情。
- 优先使用当前快照中的完整 SessionActivity，不把 relatedUsage 投影伪装为完整详情。缺失时按来源和当前实际期间读取一次完整快照，缓存兄弟会话并合并并发请求；名字悬停或键盘聚焦时按需预取。
- 全链路使用父详情的实际时间范围；独立打开携带来源、精确 ID 和期间。既有通知入口继续查询已采集历史。
- 加载、未找到和失败都保留返回，失败可重试。原有操作、模型、计价、活动及元信息保留。
- 复用共享 Dashboard 组件与两端 transport，不引入依赖；更新 UI 规范、四语言文案及 changeset。

## 方案比较

同一弹窗内导航最适合连续查看，保留父状态；新标签页/独立窗口适合并排比较，保留为辅助入口。默认独立打开会增加页面和重复加载；叠加多层 Modal 会增加焦点、关闭和滚动复杂度，因此采用单一 Modal。

## 验收

验证缓存命中零详情读取、同来源并发合并、失败重试及范围隔离；实际两端 UI 检查父子往返、折叠/范围/滚动/焦点恢复、加载失败可返回、独立打开和既有详情功能。运行两端构建、类型检查、相关测试及合成 UI 验收。真实用户数据耗时没有测量时不承诺具体速度。
