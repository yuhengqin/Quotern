# 会话模型用量与计价明细

用户已在会话中选择“模型汇总行 + 就地展开计价明细”，并明确要求不保留界面中的技术依据。

- 主表保留模型、总 Token、未缓存输入、缓存读取、缓存写入、输出（含推理）、已知请求和费用；多模型与未归属差额的合计规则不变。
- 每个模型通过有明确名称、可用键盘操作的按钮展开同一行下方的计价明细，展示项目、用量、单价（USD / 1M tokens）和分项费用；默认收起。
- 移除表下统一计算依据卡片，不再展示价格表标识、匹配模型、匹配方法、规则引用等技术依据。
- 保留费用来源、未知/未计价/不完整状态和影响结果的估算假设；当前参考价仍通过现有独立价格页查看。
- 分项费用必须复用 Core 实际计价的分组结果，覆盖请求档位、输入阈值与缓存 TTL；不得用模型汇总用量乘基础价伪造对账。
- 来源只上报总费用、旧 runtime 或明细不足时，保留总费用与可用用量/参考单价，无法确认的分项费用显示未知并明确说明。
- 数量、金额和单价复用现有格式化与偏好；原始 API/导出精度不变。输出包含推理，不重复相加。
- Dashboard 和 Desktop 通过共享组件保持一致，覆盖窄屏、深浅色和键盘交互。

## 方案取舍

采用模型行展开，使比较模型与核对费用分别发生在主表和紧邻明细中。单价直接常驻每个用量格会增加主表密度；用量/价格页签会要求用户来回切换，均不采用。

## 验收

保留原主表和会话动作；单/多模型、关联范围切换、多费率、记录金额、部分未计价与旧 runtime 均不误标或误算。两端构建、类型检查、相关回归和合成界面验收通过，并查看截图。
