# 会话查询缓存、分页与按需详情

用户已选择缓存历史整理与范围汇总、服务端分页和按需详情，并要求补齐分页。目标是在大量会话下减少重复计算、响应体和首屏等待，保留当前统计口径及全部操作。

## 方案与边界

采用同一查询服务的分层缓存和独立列表/详情接口。仅缓存现有全量接口仍会传输所有详情；仅前端分页不能减少接口工作，均不满足本次要求。旧 `tud-session-activity` 保留兼容，列表与详情共用历史和计价准备结果。

- 已整理历史以来源快照身份缓存；每次读取检查文件变化，来源增删、同步更新后失效。缓存不跨数据目录混用，数量有界，并发相同请求合并。
- 范围汇总按历史版本、实际时间窗口、来源、bucket 版本和有效定价缓存；账号名称和外部会话标题保持新鲜。缓存中对象不得被请求后续处理污染。
- 新列表接口在完整范围内筛选、排序、构建根/子关系，再按根会话分页，只返回当前页的轻量行和关联树、完整筛选选项及分页统计。统计分母保持原范围。时长排序可按需补算范围内时长；常规列表不计算完整详情。
- 新详情接口按身份与冻结窗口读取，只计算目标及其关联成员需要的模型明细、时长、活动与关系汇总。列表行显式标记为摘要，不能冒充完整缓存；根详情和关联详情均有加载、失败、重试及返回。
- CSV 导出完整匹配集合，保留原始数值与安全转义，不受当前页裁剪。

## 分页与交互

默认每页仍为 12 个根会话；增加 12/24/48 每页条数、页码（含首末页和省略号）、直接跳页及当前根会话范围/总数。页码与页容量写入 URL，刷新和浏览器前进后退可恢复。筛选、排序、时间和页容量改变重置页码；越界响应规范化 URL。翻页保留控件焦点并让结果顶部可见，窄屏不横向溢出。

继续保留搜索、来源、项目、模型、账单归属、日期/项目分组、排序方向、子项模型筛选、关联详情栈、通知定位和总览六条预览。旧 runtime 和只读演示降级沿用旧接口并在前端分页，不能把未知指标显示为零。Dashboard/独立 Desktop hook 同步，复用现有 HeroUI Pagination/FilterMenu/数字格式入口。

## 验收

测试覆盖根分页、子项不丢失、筛选后计数、稳定排序、越界、页容量、全量导出、按需详情、缓存复用/并发合并/同步和定价失效/数据目录隔离。运行相关 Core 与 Dashboard 测试、两端类型检查和构建；使用隔离只读 API 及真实浏览器验证分页、详情、键盘和窄屏，比较同一份真实已采集数据的冷/热列表与翻页耗时。现有服务不停止或接管。
