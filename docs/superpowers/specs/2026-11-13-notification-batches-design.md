# 集中提醒与全部关闭

用户已确认采用「集中提醒合并 + 全部关闭」，普通反馈自动收起，紧急通知及时发送。

- Desktop 的普通额度、重置及服务状态通知在固定 1 秒窗口内合并。同一账号/窗口仍仅保留最新事件；额度耗尽和严重服务中断立即发送。开发测试通知保持立即发送。
- 单项保留现有正文和精确定位。多项显示数量及最多三项标题，查看进入额度面板，全部业务信息仍从各账号/服务详情查看。暂缓按原始事项分别管理，重置/恢复不重新提醒。
- Windows 原生通知提供「关闭全部提醒」动作；设置「通知」页提供相同操作，作为其他平台和原生注册失败时的入口。只清理本进程管理的当前通知、待合并事项和暂缓事项；不修改提醒偏好，未来新事件仍生效。
- 单项替换、偏好变化、账号变化、状态恢复、过期、暂停、退出必须同时处理合并队列和各原始事项。Windows 横幅超时仍保留通知中心撤回能力。合并中的某项失效时，剩余事项重新呈现但不重复播放提示音。
- 系统控制原生横幅的自动收起；不强制用户逐条处理。应用内短暂成功 Toast 沿用现有自动消失策略。

采用现有 NotificationManager 承担投递和生命周期，在其中增加可选合并配置；摘要文案单独负责四语言输出。保留 Electron 原生外壳和现有身份/协议安全边界，不引入通知中心或新的持久化格式。

取舍：仅加关闭按钮无法减少集中弹出；仅合并无法处理历史堆积。两者一起实施。原生按钮呈现受平台限制，设置入口始终可访问；不承诺清除应用重启前遗留的系统历史。

验证：真实计时器替身覆盖合并、紧急绕过、替换、逐项过期/策略撤回、暂缓、全部清理和迟到事件；真实 IPC/协议及设置键盘操作 smoke；Windows 隔离 AppID 检查原生历史。macOS/Linux 的原生呈现未在 Windows 上验证。
