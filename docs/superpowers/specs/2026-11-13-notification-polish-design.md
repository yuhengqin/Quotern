# Desktop 通知体验优化

用户已要求落地前一轮对比提出的四项：应用身份、快捷操作、服务正文、过期通知处理。

## 方案与边界

- 保留 Electron 35.4.0 和现有 NotificationManager，不新增原生依赖。
- Windows 用当前用户的 AppUserModelId DisplayName/IconUri 注册补全 Quotern 名称与图标；正式身份仍为 `dev.quotern.desktop`。隔离实例使用基于 profile 的独立身份，退出时只清理自己的临时注册。
- Windows toast XML 提供「查看详情」「30 分钟后提醒」。Electron 35 不返回按钮参数，因此用专用 URI 协议激活一个仅转发命名管道消息的 bootstrap 分支；该分支不进入采集、实例抢占或窗口启动。每个运行实例持有随机管道与令牌，失效/伪造动作无效。开发态/portable 注册正确入口，避免激活正式 runtime。
- 不采用 foreground 按钮（无法区分动作），也不新增常驻 PowerShell 通知代理。其他系统保留原生正文点击，macOS 可用原生 action 按钮。
- 服务正文先给故障程度和已订阅的受影响组件，再给最新事件标题/摘要；不转发未选择的组件，正文不解释内部实现。
- 额度按厂商+已验证账号（否则 reader）+窗口替换；服务按厂商替换。保持 Core 原有基线、阈值、事件去重和通知开关。使用当前状态静默清理失效预警；恢复/重置保留短期通知，unknown/stale 不视为恢复。
- 暂缓仅影响同一通知范围，30 分钟后按最新有效状态重发；状态恢复、规则关闭、账号移除和退出均取消，其他范围不受影响。非持久化，重启不会补发。
- 退出、过期、替换或已查看后撤销对应系统条目。后台失焦策略、提示音、测试反馈和精确导航保留。

## 验收

针对真实通知 XML、动作转发、暂缓计时、过期清理、账号/窗口隔离、未知读数、组件选择及四语言正文运行测试。构建、Desktop 类型检查、现有通知 UI 检查必须通过；Windows 使用隔离 profile 和真实系统 Toast 验证名称/图标、两种按钮和通知中心清理。打包安装/portable 外层启动器与 macOS/Linux 不能用开发态测试代替。
