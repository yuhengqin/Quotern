# 模型价格多源补缺、同步检查与持续刷新

用户已确认执行比较中提出的四项改进：LiteLLM 补缺、同步差异检查、特殊费率转换、长期运行的过期刷新。本设计将该范围具体化；实现由主代理在本会话完成，不改已有计量事实或来源报告金额。

## 取舍

- 保留 models.dev `catalog.json` 为主源，继续使用其官方渠道筛选、模型元数据和独立订阅目录。LiteLLM 只补充同厂商直连的文本模型及明确发布的缺失字段，不接入 OpenRouter 转售价格，不用网关条目推导原厂价格。
- 不整体切换 LiteLLM，也不把两张表无条件展开合并：这会破坏渠道身份与人工补充的优先级。运行时与底表脚本使用同一个纯转换入口。
- 不采用固定倍率猜测特殊档位。只转换已确认的长上下文、priority/flex、Anthropic fast、5m/1h 写缓存字段；已有人工规则优先处理相同条件。
- 默认每 24 小时重验证，失败至少间隔一小时重试；Desktop resume 共用过期检查，不重启 runtime、不触发采集。保留启动先用缓存、最多等待三秒的行为。

## 数据与优先级

1. 独立用户单价层继续优先，删除后恢复当前参考价。
2. models.dev 的新有效官方文本价格更新参考表，保留人工条目、明确别名、订阅元数据及人工 request_rules。
3. LiteLLM 通过 `litellm_provider` 白名单与 key 形态共同识别原厂渠道，生成带 provider 的明确 ID；不从 reseller 的裸名推导官方价。
4. LiteLLM 仅新增缺失 ID。可补已有 ID 的缺失缓存费率，但须基础 input/output 完全一致；发生冲突时保留主源并记录差异。
5. 缺失、null、非有限、负值均不变成零价；明确的合法零值保留。上游删除曾同步的 ID 时保留最后已知价并标记沿用旧价，不删除人工补充。

`price_metadata` 按定价 ID 保存来源、最近确认时间、沿用状态及可选补充字段来源；`_meta.sync_report` 保存有界的差异摘要（新增、改价、沿用、缺字段、冲突、显著变价及失败源）。这些是检查记录，不是供应商调价时间。

同步脚本输出完整计数与有限差异；运行时记录/公开安全摘要。正常数据不新增正文标签，沿用旧价等影响判断的状态在渠道详情可查看；价格页既有“数据说明”呈现来源及检查摘要。两端复用现有共享页面。

## 特殊费率

- LiteLLM 基础费率为 USD/token，转为现有 USD/1M Token。
- 长上下文规则只用完整单请求输入，GPT/Claude 的阈值严格大于；半小时累计、未知输入不触发。
- 将明确的服务档位和上下文组合分别转为规则；未发布组合不擅自相乘。Anthropic 明确 fast 倍率允许作用于其发布的费率。
- 自动规则带来源标识、参考 URL 和逐字段基准/倍率，用户修改基础价后仍按已发布关系修饰；手工 request_rules 维持绝对报价语义和时间界限。
- 更新时只重建本来源的自动规则，失败源保留上次有效规则；不得删除人工规则。计价版本指纹包括实际费率/匹配/规则/用户单价与算法修订，不因检查时间单独变化而使全部费用缓存失效。

## 网络与生命周期

- 默认来源并行请求 models.dev 与 LiteLLM，共享 30 秒的取消/超时边界；单源失败可使用另一有效源，失败源保留最后有效数据。两源都不可用时保留原表。
- 用户配置的自定义 Quotern JSON 地址保持独立，不额外请求公共源。
- 每个刷新句柄最多一个 timer 和一个在途请求；timer/resume 合并，stop 清 timer、取消请求，旧代不得应用内存或覆盖磁盘。使用原子发布，并串行化同进程保存。
- `ttlMs` 恢复为持续运行时的过期时长，默认 24h；历史遗留 60s 默认迁移为 24h，明确的其他自定义值保留。启动仍主动验证一次。
- 参考价未变化时只更新检查元数据，不重算历史费用；实际费率变化后沿用现有失效/通知链路。历史重算先按日期分组，避免日期数乘全历史扫描；运行时结束后不发布旧代结果。
