# 会话计价项目合并与分档详情

用户已确认：重复计价项目合并，每项目一行；点击单价查看各档用量、实际单价与费用；按照实际规则注明长上下文及 Fast/Flex，网页与桌面一致。

## 实现边界

- Core 在实际计算分项时提供可选的结构化 `conditions`：已应用的 Fast/Flex、输入下界和上界。每个费率字段采用最终生效规则的条件，不按金额猜测。基础档上界只来自同优先级、同字段的有效长度规则；未知请求长度不补造上下文档位。
- 会话与跨关联会话合并使用「类别＋实际单价＋条件」作为身份，保留同为 $4 的常规 Fast 与常规服务长上下文两档。原有旧 runtime 无条件数据仍可读，标注条件未记录。
- 模型展开默认仅有未缓存输入、缓存读、缓存写、输出（含推理）四项。TTL 缓存写合并到同一项，档位内保留寿命。零、未知、已知小计和来源报告金额语义不变。
- 单价最多并列两个不同值，更多时用档位数量表达；实际存在多个条件但金额相同时，仍可点单价查看各档。点击打开非模态 HeroUI Popover，展示适用条件、Token 用量、单价（/1M Token）与分项费用；Escape 关闭并回到入口，主详情保持打开；外部点击及祖先滚动关闭，内部可滚动。
- 使用现有格式化入口；Token 与阈值遵循单位偏好，报价基准固定 /1M Token；四语言一致。长上下文说明：单次完整输入含缓存，阈值命中后整次请求计价。
- 复用共享 SessionUsageBreakdown 与 session-detail 数据投影。Desktop 已 re-export 共享会话组件并登记其 CSS；不创建独立副本。
- HelpPopover 固定为帮助图标，FilterMenu 面向筛选选项，均不适合单价触发器；分档入口直接组合已有 HeroUI Popover，保持相同关闭、视口和焦点约束。
- 保留现有费用算法、历史规则边界、来源费用、旧 runtime 回退、参考价格跳转与其余会话功能。不读取或修改用户统计数据。

## 验证

先测实际规则条件与同价不同条件的合并，再实现。检查四项汇总、TTL、零/未知、小计和输入不变；执行 Core、Dashboard 测试与双端类型检查/构建。扩展现有 session-detail UI smoke，共用 fixture 覆盖 HTTP/IPC、多档点击、条件区分、Escape/焦点、窄屏、单位切换和四语言，并查看截图。
